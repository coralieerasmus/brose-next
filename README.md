# Brosé — "the new ritual."

The website for Brosé, a rosé wine brand. Built with Next.js (App Router) and Three.js. A single-page experience: a dark, mouse/tilt-reactive hero, then a pinned 3D sequence where the bottle turns, falls, and hands off into an info-cards section.

## Stack

- **Next.js 16.3.6** (App Router) + **React 19.2** + **TypeScript**
- **Three.js** (`^0.186.0`) for the 3D bottle (loaded via `GLTFLoader`, lit with a `RoomEnvironment` + `PMREMGenerator`)
- **styled-jsx** for all component styling — no separate CSS files per component, styles live inline in each `.tsx`. Tailwind is present in `package.json` (left over from the `create-next-app` scaffold) but isn't actually used anywhere in this build.
- Path alias `@/*` → project root (see `tsconfig.json`), if you want it for future files — nothing currently uses it.

## The Bottle Ritual sequence

`BottleRitual.tsx` is a single pinned, viewport-height section (`#ritual-wrap`) that plays through several phases as the user scrolls, driven by one `requestAnimationFrame` loop rather than CSS `position: sticky` (sticky turned out to be unreliable across the ancestor chain — the pin is done by JS toggling `position: fixed`/`absolute` every frame instead).

**Phase order:**

1. **`rotate`** — scroll-driven. Lion, lace mat, and bottle are all pinned; scrolling only spins the bottle (one full turntable rotation).
2. **`falling`** — triggers automatically once rotation completes. Scroll **locks** (wheel/touch/keys blocked, and a scrollbar-drag is caught and snapped back). The bottle falls with a real perspective camera — tumbling, the camera dropping *with* it, FOV widening for a speed cue — then lands with a squash-and-settle impact.
3. **`landed` → `word`** — 2 seconds after landing, "Unbreakable" fades in behind the bottle (rendered before the canvas in the DOM, so the transparent-background canvas shows it through and the bottle itself occludes it), with a warm backlight glow.
4. **`wave`** — a black wave rises to cover the screen.
5. **`cards`** — three info cards slide in from both sides. Click one to expand it (accordion — one open at a time). Scroll unlocks here.
6. **Reverse phases** (`uncards → unwave → unword → unfalling`) — scrolling back up while in the cards phase plays the entire cinematic in reverse and lands back in `rotate`, rather than just snapping away.

There's also a **watchdog**: if any locked phase runs more than 8 seconds (should never happen in the normal path — this only fires if something's actually gone wrong, e.g. the tab was backgrounded and `requestAnimationFrame` got throttled, or the WebGL context was lost), it force-resolves to a sensible endpoint and unlocks scroll, so the page can't get permanently stuck.

### Tunable constants

All in `BottleRitual.tsx`, worth knowing about if something needs adjusting:

| Constant | Default | Controls |
|---|---|---|
| `ROTATIONS` | `1` | Full turns during the rotate phase |
| `FALL_MS` / `IMPACT_MS` | `950` / `380` | Fall duration / landing squash-settle duration |
| `WORD_DELAY_MS` | `2000` | Delay after landing before "Unbreakable" appears |
| `WORD_HOLD_MS` | `1800` | How long the word stays up before the wave starts |
| `WAVE_MS` | `3000` | Duration of the wave rising (and its reverse) |
| `BASE_FOV` / `CAM_DISTANCE` | `32` / `900` | Camera framing — also determines `restY`/`landedY` (resting and landed bottle positions), since those are computed from the visible frustum, not hardcoded |
| `ROUGHNESS_FLOOR` / `ENV_MAP_INTENSITY` | `0.5` / `0.5` | Softens the bottle's metal material so it reads as brushed rather than mirror-chrome |
| `getTargetHeight()` | `380` under 760px width, else `260` | Bottle's on-screen size — bumped up on mobile since the same world-unit height reads smaller on a tall narrow viewport |
| `WATCHDOG_MS` | `8000` | Stuck-phase failsafe threshold |

## Other things worth knowing

- **Age gate** (`SiteChrome.tsx`): 18+ check, remembered via `localStorage` (`brose-age-verified`) so returning visitors aren't asked again. "No" redirects out. Clearing that localStorage key (or an incognito window) is how to see it again during testing.
- **Audio autoplay**: browsers block autoplay-with-sound without a user gesture. Playback starts on the exact click of "Yes" on the age gate — the one gesture guaranteed to happen site-wide.
- **Scroll restoration is disabled** (`history.scrollRestoration = "manual"` in `SiteChrome.tsx`), and scroll is forced to `(0, 0)` on load. Without this, browsers try to restore your exact previous scroll position on refresh, which on this site meant reloading could dump you mid-way into the ritual section instead of the hero.
- **Mobile tilt control**: the hero's darkness-reveal effect uses `DeviceOrientationEvent` on touch devices. This requires a secure context (HTTPS) — it won't work over a plain `http://` local-network address, and it can't be tested via a desktop browser's device-emulation mode unless that browser's sensor-simulation panel is explicitly turned on (no real gyroscope to read otherwise).
- **`.stage`'s `touch-action`** is `pan-y`, not `none` — it was originally `none` to stop the page panning while dragging to control the reveal, but that also blocked the vertical swipe needed to scroll past the hero entirely. `pan-y` allows vertical scroll while still suppressing horizontal drag/pinch.
